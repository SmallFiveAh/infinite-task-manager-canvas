# React 模式

> 构建生产级 React 应用的原则。

---

## 1. 组件设计原则

### 组件类型

| 类型 | 用途 | 状态 |
|------|------|------|
| **服务端组件** | 数据获取、静态内容 | 无 |
| **客户端组件** | 交互性 | useState、effects |
| **展示组件** | UI 展示 | 仅 props |
| **容器组件** | 逻辑/状态 | 繁重状态 |

### 设计规则

- 每个组件单一职责
- Props 向下传递，事件向上传递
- 组合优于继承
- 优先选择小巧、专注的组件

---

## 2. Hook 模式

### 何时提取 Hooks

| 模式 | 提取时机 |
|------|---------|
| **useLocalStorage** | 需要相同存储逻辑时 |
| **useDebounce** | 多个防抖值时 |
| **useFetch** | 重复的 fetch 模式 |
| **useForm** | 复杂表单状态 |

### Hook 规则

- Hooks 只能在顶层调用
- 每次渲染保持相同顺序
- 自定义 Hook 以 "use" 开头
- 组件卸载时清理 effects

---

## 3. 状态管理选择

| 复杂度 | 解决方案 |
|--------|----------|
| 简单 | useState, useReducer |
| 共享局部 | Context |
| 服务端状态 | React Query, SWR |
| 复杂全局 | Zustand, Redux Toolkit |

### 状态放置

| 作用域 | 位置 |
|--------|------|
| 单个组件 | useState |
| 父子组件 | 提升状态 |
| 子树 | Context |
| 应用级 | 全局 store |

## 4. React 19 模式

### 新增 Hooks

| Hook | 用途 |
|------|------|
| **useActionState** | 表单提交状态 |
| **useOptimistic** | 乐观 UI 更新 |
| **use** | 在渲染中读取资源 |

### 编译器优势

- 自动记忆化
- 减少手动 useMemo/useCallback
- 专注于纯组件

---

## 5. 组合模式

### 复合组件

- 父组件提供 context
- 子组件消费 context
- 灵活的插槽式组合
- 示例：Tabs、Accordion、Dropdown

### Render Props 与 Hooks

| 使用场景 | 优先选择 |
|----------|----------|
| 可复用逻辑 | 自定义 Hook |
| 渲染灵活性 | Render props |
| 横切关注点 | 高阶组件 |

---

## 6. 性能原则

### 何时优化

| 信号 | 操作 |
|------|------|
| 渲染缓慢 | 先分析性能 |
| 大型列表 | 虚拟化 |
| 计算昂贵 | useMemo |
| 稳定回调 | useCallback |

### 优化顺序

1. 确认是否真的慢
2. 使用 DevTools 分析
3. 识别瓶颈
4. 应用针对性修复

---

## 7. 错误处理

### Error Boundary 使用

| 作用域 | 放置位置 |
|--------|----------|
| 应用级 | 根级别 |
| 功能模块 | 路由/功能级别 |
| 组件 | 高风险组件周围 |

### 错误恢复

- 显示备选 UI
- 记录错误
- 提供重试选项
- 保留用户数据

## 8. TypeScript 模式

### Props 类型定义

| 模式 | 用途 |
|------|------|
| Interface | 组件 props |
| Type | 联合类型、复杂类型 |
| Generic | 可复用组件 |

### 常见类型

| 需求 | 类型 |
|------|------|
| 子节点 | ReactNode |
| 事件处理 | MouseEventHandler |
| Ref | RefObject<Element> |

## 9. 测试原则

| 层级 | 关注点 |
|------|--------|
| 单元测试 | 纯函数、hooks |
| 集成测试 | 组件行为 |
| 端到端测试 | 用户流程 |

### 测试优先级

- 用户可见行为
- 边界情况
- 错误状态
- 可访问性

---

## 10. 反模式

| ❌ 避免 | ✅ 推荐 |
|---------|---------|
| 深度传递 props | 使用 context |
| 巨型组件 | 拆分为小组件 |
| 什么事都用 useEffect | 服务端组件 |
| 过早优化 | 先分析性能 |
| 索引作为 key | 稳定的唯一 ID |

---

> **记住：** React 的核心是组合。构建小组件，深思熟虑地组合。
